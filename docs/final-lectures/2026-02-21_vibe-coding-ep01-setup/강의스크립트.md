## [0:00~0:45] 섹션 1: 인트로 — "10분 뒤 여러분 화면에 웹사이트가 뜹니다"

**[화면]** 완성된 포트폴리오 웹사이트가 브라우저에서 열려 있는 장면. 세련된 프로필 섹션, 기사 목록 그리드, 연락처까지 갖춘 원페이지 사이트. 3초간 천천히 스크롤. 화면 전체에 살짝 글로우 이펙트.

**[발화]**
> 자, 이거 보이시나요? 이게 오늘 영상의 최종 결과물입니다. 포트폴리오 웹사이트예요. 상단에 프로필, 가운데에 작업물 목록, 하단에 연락처까지 깔끔하게 들어가 있죠. 이걸 코딩 한 줄 모르는 사람이, AI한테 한국어로 "만들어줘"라고 해서 만든 겁니다. 10분 뒤에 여러분 화면에도 이게 뜹니다. 믿기 어려우시죠? 근데 진짜예요.

**[자막]** `10분 뒤, AI가 만든 웹사이트가 여러분 화면에 뜹니다`

**[발화]**
> 이 영상은 총 8편짜리 바이브 코딩 시리즈의 첫 번째예요. Phase 1에서는 설치하고, 웹 화면 띄우고, 에러 잡는 법까지. Phase 2에서는 로그인이랑 데이터베이스를 붙이고, 오픈소스도 활용해봐요. Phase 3에서는 실전 프로젝트를 만들어서 전 세계에 배포합니다. 오늘은 이 중에서 1편, 설치와 세팅이에요.

**[화면]** 오늘의 학습 목표 4가지가 하나씩 등장하는 그래픽
```
1. 개발 용어 첫인상 — 대화에 나와도 겁먹지 않을 정도로 감잡기
2. 터미널 첫 경험 — 검은 화면을 열고 명령어 복붙 해보기
3. AI 프롬프팅 감잡기 — 대충 시키기 vs 구체적으로 시키기의 차이 체감
4. 첫 결과물 목격 — AI가 웹페이지를 만드는 과정을 직접 보기
```

**[발화]**
> 오늘 끝나면 여러분이 가져가는 게 딱 네 가지예요. 첫째, 개발 용어가 대화에 나와도 겁먹지 않을 정도로 감을 잡게 됩니다. 완벽하게 이해하는 게 아니라, 시작하는 데 무리 없을 만큼요. 둘째, 까만 화면 — 터미널이라고 하는데 — 이걸 직접 열어보고 명령어를 복붙하는 경험을 합니다. 셋째, AI한테 대충 시키는 거랑 구체적으로 시키는 거, 그 차이를 직접 체감해요. 넷째, 이게 제일 중요한 건데, AI가 코드를 만들어서 웹사이트가 뜨는 과정을 눈으로 직접 보게 됩니다. 다 이해 못 해도 괜찮아요, 오늘은 "와, 이게 되네?"를 느끼는 게 목표입니다. 자, 시작해볼까요?

## [0:45~2:00] 섹션 2: 바이브 코딩이란? — "AI한테 한국어로 시키면 끝"

**[화면]** "바이브 코딩이란?" 타이틀 카드. 이후 claude.ai와 Claude Code 비교 그래픽 등장. (PPT p4 기반)

**[발화]**
> 본격적으로 시작하기 전에, 오늘 우리가 쓸 도구부터 정리하고 갈게요. 혹시 Claude라고 들어보셨어요? AI 챗봇인데, 두 가지 버전이 있어요. 하나는 claude.ai. 이건 웹 채팅이에요. 브라우저에서 질문하고, 글 쓰고, 분석하고 하는 거. 비유하자면 전화로 요리법 물어보는 거예요. "파스타 어떻게 만들어요?" 하면 레시피를 말로 알려주는 거죠. 근데 오늘 우리가 쓸 건 Claude Code라는 거예요. 이건 달라요. 셰프가 직접 우리 주방에 와서 요리를 해주는 거예요. 터미널에서 파일을 읽고, 만들고, 수정까지 해주는 코딩 전문 도구입니다. Claude PRO 계정 하나로 둘 다 쓸 수 있고요, 이번 시리즈에서는 Claude Code를 주로 사용합니다.

**[자막]** `claude.ai = 전화로 레시피 물어보기 / Claude Code = 셰프가 주방에서 직접 요리`

**[화면]** "바이브 코딩" 정의 슬라이드 (PPT p11 기반). Andrej Karpathy 사진과 인용문.

**[발화]**
> 자, 그럼 "바이브 코딩"이 정확히 뭐냐. 2025년에 Andrej Karpathy라는 분이 이 개념을 제안했어요. 이분이 누구냐면, 전 테슬라 AI 디렉터 출신이에요. 이분이 뭐라고 했냐면, "사람의 언어로 지시하면 AI가 코드를 대신 짜주는 것, 이게 바이브 코딩이다." 복잡한 문법이나 코딩 문법을 전혀 몰라도 누구나 소프트웨어를 만들 수 있다는 거예요. 저도 개발자 출신이 아닌데, 이 방식으로 여러 가지를 만들어봤거든요. 진짜 됩니다.

**[화면]** Before vs After 비교 그래픽 (PPT p12 기반). 왼쪽에 기존 방식(긴 화살표), 오른쪽에 바이브 코딩(짧은 화살표).
```
기존: 아이디어 → 개발자 채용/외주 → 수개월 개발 → 3~6개월 이상
바이브: 아이디어 → AI에게 설명 → 실시간 코드 생성 → 수시간 내
```

**[발화]**
> 기존에는 뭔가 만들고 싶으면 어떻게 했어요? 개발자를 채용하거나 외주를 줬죠. 그러면 3개월에서 6개월은 기본이에요. 돈도 몇백에서 몇천만 원이 들고요. 근데 바이브 코딩은? 아이디어가 있으면 AI한테 설명해요. 그러면 실시간으로 코드가 생성돼요. 몇 시간이면 돌아가는 프로토타입이 나옵니다. 이게 세상이 바뀐 거예요.

**[화면]** 삼성전자 실적 분석 사례 그래픽 (PPT p21-22 기반). 왼쪽에 기존 방식(OpenDART 수동 복사, 3~4시간~2일), 오른쪽에 바이브 코딩(프롬프트 한 줄, 10분).

**[발화]**
> 꼭 제품을 만드는 것만 바이브 코딩이 아니에요. 실제 업무에도 바로 쓸 수 있습니다. 예를 들어, 시장조사를 위해 삼성전자 매출을 분석한다고 해볼게요. 기존에는 OpenDART라는 사이트에 들어가서, 데이터를 하나하나 수동으로 복사하고, 엑셀에 붙여넣고, 정리하고... 이거 빨라야 3~4시간, 느리면 이틀 걸리는 작업이에요. 근데 바이브 코딩으로 하면? 프롬프트 한 줄 딱 넣으니까, AI가 알아서 API 연동하고, 데이터 179개 레코드를 자동으로 수집하고, 사업부별 매출, 지역별 매출, 주가까지 통합 분석해서 시각화까지 해줬어요. 10분 만에요. 10분. 이게 바이브 코딩의 위력입니다.

**[자막]** `삼성전자 5년 실적 분석: 기존 3~4시간 → 바이브 코딩 10분`

### 3-1. 컴퓨터 언어 [약 30초]

**[화면]** PPT p5-6 기반 그래픽. 0과 1 → 프로그래밍 언어 → 자동 번역 과정을 보여주는 플로우차트.

**[발화]**
> 첫 번째, 컴퓨터 언어. 컴퓨터는 기본적으로 0과 1만 이해해요. 근데 사람이 0이랑 1로 대화하면 미치겠죠? 그래서 사람이 읽기 쉬운 언어를 만든 거예요. Python이니 JavaScript니 하는 것들이요. 이건 마치 외국어랑 비슷해요. 한국어, 영어, 일본어가 있듯이 프로그래밍 언어도 여러 개가 있고, 각각 잘하는 분야가 달라요.

**[화면]** Python과 JavaScript를 나란히 비교하는 카드 그래픽.
```
Python — 데이터 분석/AI 전문가. 문법 간결. 영어와 비슷.
JavaScript — 웹 브라우저의 주인. 웹사이트를 움직이게 하는 유일한 언어.
```

**[발화]**
> Python은 데이터 분석이랑 AI 쪽 전문가예요. 문법이 간결해서 영어 읽듯 읽을 수 있어요. JavaScript는 웹 브라우저의 주인이에요. 여러분이 보는 모든 웹사이트? 전부 JavaScript가 움직이게 하는 거예요. 오늘 우리는 웹사이트를 만들 거니까 JavaScript를 쓸 겁니다.

**[자막]** `오늘의 선택: JavaScript (웹사이트 만들기)`

### 3-2. 폴더와 파일 [약 20초]

**[화면]** PPT p7 기반. 프로젝트 폴더 구조 그래픽.
```
my-project/
  ├ index.html (뼈대)
  ├ style.css (디자인)
  └ script.js (동작)
```

**[발화]**
> 두 번째, 폴더와 파일. 폴더가 뭐냐면요, 하나의 프로젝트 단위예요. 웹사이트 하나를 만들면, 그 웹사이트가 실제로 동작하기 위한 파일들이 하나의 폴더 안에 모여 있어요. 그 안에 index.html은 웹사이트의 뼈대, style.css는 디자인, script.js는 동작을 담당해요. 이 파일들이 합쳐져서 하나의 웹사이트가 돌아가는 거예요. 이름만 알아두시면 돼요, 외울 필요 없어요.

**[자막]** `프로젝트 = 하나의 폴더 안에 뼈대(html) + 디자인(css) + 동작(js)`

### 3-3. 터미널 [약 30초]

**[화면]** PPT p8-9 기반. 터미널 화면과 카카오톡 채팅 화면을 나란히 보여주는 비교 그래픽.

**[발화]**
> 세 번째, 터미널. 여러분이 제일 무서워하는 그 까만 화면이에요. 근데요, 이거 카카오톡 채팅창이에요. 진짜로요. 카톡에서 친구한테 메시지 보내잖아요? 터미널에서는 컴퓨터한테 메시지를 보내는 거예요. 마우스 클릭 대신 글자로 명령을 내리는 거죠. Windows에서는 PowerShell, Mac에서는 Terminal이라고 불러요.

**[화면]** 기본 명령어 4개가 카드 형태로 등장.
```
cd — 폴더 이동 ("카톡방 이동")
dir/ls — 파일 목록 보기 ("카톡방 사람 확인")
mkdir — 새 폴더 만들기 ("새 카톡방 개설")
```

**[발화]**
> 명령어 기본 4개만 알면 충분해요. `cd`는 폴더를 이동하는 거예요. 카톡방 옮기는 것처럼요. `dir`이나 `ls`는 이 폴더 안에 뭐가 있는지 보는 거. `mkdir`는 새 폴더 만드는 거. 이 세 개만 알면 터미널 어디든 돌아다닐 수 있어요. 까만 화면이 무서워 보이지만, 그냥 카톡 입력칸이라고 생각하세요. 잘못 쳐도 컴퓨터 안 망가집니다. 제가 보장합니다.

**[자막]** `터미널 = 컴퓨터와 카카오톡 채팅. 뭘 쳐도 안 망가져요!`

### 3-4. 웹의 구조 [약 20초]

**[화면]** PPT p25 기반. 레스토랑 비유 그래픽. 건물(프로젝트) 안에 홀(프론트엔드)과 주방(백엔드), 건물이 서있는 땅(서버).

**[발화]**
> 네 번째, 웹의 구조. 레스토랑으로 비유해볼게요. 서버는 건물이 서있는 땅이에요. 24시간 가동되는 부지. 프로젝트 폴더는 그 위에 세워진 건물이고요. 그 건물 안에 두 공간이 있어요. 하나는 홀, 하나는 주방. 프론트엔드가 홀이에요. 손님이 보는 화면, 메뉴판, 예쁜 인테리어. 백엔드가 주방이에요. 데이터를 처리하고 요리하는 곳. 오늘은 홀만 만들 거예요. 주방은 4편에서 합니다! 참고로, 오늘 만드는 레스토랑은 아직 "우리 집 안"에서만 영업하는 거예요. 내 컴퓨터에서만 보이는 거죠. 이걸 "로컬"이라고 하는데, 나중에 인터넷에 올려서 진짜 오픈하는 건 마지막 섹션에서 다시 설명드릴게요.

**[자막]** `프론트엔드(홀) = 손님이 보는 화면 / 백엔드(주방) = 데이터 처리`

### 3-5. GitHub [약 20초]

**[화면]** PPT p26 기반. GitHub 로고 + 구글 드라이브 비교 그래픽. 타임머신 일러스트.

**[발화]**

**[자막]** `GitHub = 코드의 구글 드라이브 + 타임머신`

### 3-마무리: 브릿지

```

```

**[발화]**


**[자막]** `AI 3원칙: ① 맥락 제공 ② 구체적 요청 ③ 단계별 지시`
