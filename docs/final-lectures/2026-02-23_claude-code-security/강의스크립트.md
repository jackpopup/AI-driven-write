**러닝타임**: 약 15분
**핵심 메시지**: "보안 리뷰를 사람이 하던 시대에서, AI가 하는 시대로 넘어가고 있습니다. 그 전환의 시작점이 `/security-review` 한 줄입니다."

## [0:25~2:00] 섹션 2: 문제 제기 -- 보안 사고 사례 + 기존 도구의 한계

### 슬라이드 2: 보안 사고는 남의 일이 아닙니다
- **시간**: 0:25 ~ 1:00
- **화면**: 최근 보안 사고 사례 2~3개를 뉴스 카드 형태로 배치. 각 카드에 서비스명, 사고 유형, 피해 규모가 간결하게 표시. 전체적으로 붉은 경고 톤.

**[발화문]**
> "보안 사고, 우리 회사는 괜찮겠지." 그런데 현실을 보면요, MOVEit 공급망 공격으로 2,600개 넘는 조직이 한꺼번에 뚫렸습니다. Log4Shell은 전 세계 서버의 절반 이상에 영향을 미쳤고요. 공통점은 코드 안에 있던 취약점을 아무도 발견하지 못한 채 운영하고 있었다는 겁니다.

### 슬라이드 3: "왜 기존 도구로는 못 잡았을까?"
- **시간**: 1:00 ~ 2:00
- **화면**: 화면 중앙에 큰 물음표. 하단에 기존 SAST 도구들의 로고 나열 (SonarQube, ESLint, Semgrep 등). 각 로고 옆에 "규칙 기반 패턴 매칭" 태그. 회색 톤.

**[발화문]**
> 여러분 회사에서도 SonarQube, ESLint, Semgrep 같은 보안 도구를 쓰고 계실 겁니다. 이 도구들이 나쁜 건 아닙니다. 그런데 근본적인 한계가 있습니다. 전부 "규칙 기반 패턴 매칭"으로 동작해요. 미리 정해놓은 규칙에 맞는 패턴이 있으면 경고를 띄우는 방식입니다. 패턴은 잡지만, 맥락은 이해하지 못하는 거예요. 바로 여기서 AI가 등장합니다.

## [2:00~4:15] 섹션 3: 기존 SAST vs AI -- 패러다임의 전환

### 슬라이드 4: CCTV vs 탐정
- **시간**: 2:00 ~ 2:45
- **화면**: 화면 좌우 분할. 왼쪽(빨간 톤): CCTV 아이콘 + "기존 SAST". 불릿 3개 -- "규칙에 정의된 패턴만 탐지", "코드의 의미 이해 불가", "거짓 양성 다수". 오른쪽(초록 톤): 탐정 아이콘 + "Claude Code Security". 불릿 3개 -- "코드를 읽고 의미 추론", "비즈니스 로직 결함 탐지", "거짓 양성 최소화".

**[발화문]**
> 비유로 설명드리겠습니다. 기존 SAST는 CCTV예요. "SQL 쿼리에 사용자 입력이 직접 들어갔다"는 규칙에 맞으면 경고를 띄웁니다. 반면 Claude Code Security는 탐정입니다. 코드를 처음부터 끝까지 읽고, "이 함수에서 저 함수를 호출하는데, 이 흐름에서 권한 체크가 빠져 있다"는 식으로 추론합니다.

- **시간**: 2:45 ~ 3:15

**[발화문]**
> 하나 더. 기존 SAST는 맞춤법 검사기입니다. 오탈자는 잡지만, 글의 논리가 앞뒤가 안 맞는 건 못 잡습니다. Claude Code Security는 편집장이에요. 원고를 처음부터 끝까지 읽고, "3번째 문단의 논리가 1번째 문단과 모순된다"를 짚어냅니다.

### 슬라이드 6: 비즈니스 로직 결함 -- 핵심 차별점
- **시간**: 3:15 ~ 3:45
- **화면**: 3개의 카드: (1) "쿠폰 중복 적용" (2) "관리자 권한 우회" (3) "결제 금액 조작". 각 카드에 빨간 경고 아이콘.

**[발화문]**
> 구체적으로 보겠습니다. 쿠폰 중복 적용으로 무한 할인, 일반 사용자가 관리자 API 접근, 클라이언트에서 결제 금액 조작. 코드 문법상으로는 전혀 오류가 없습니다. 패턴 매칭으로는 절대 잡을 수 없어요. 코드의 "의미"를 이해해야만 발견할 수 있는 취약점들입니다.

## [4:15~5:30] 섹션 4: Claude Code Security 소개 -- 작동 원리

### 슬라이드 8: 어떻게 작동하는가
- **시간**: 4:15 ~ 5:00
- **화면**: 아키텍처 도식. "코드베이스" -> "Claude AI" -> "보안 리포트". Claude AI 내부 3단계: (1) "코드 읽기" (2) "맥락 추론" (3) "취약점 판단". 하단에 "모든 프로그래밍 언어 지원"

**[발화문]**
> 2026년 2월 20일, Anthropic이 공식 발표한 기능입니다. 크게 두 가지로 나뉩니다. 하나는 터미널에서 바로 쓸 수 있는 /security-review 명령어, 다른 하나는 팀 단위로 전체 코드베이스를 자율 스캔하는 웹 대시보드입니다. 오늘은 여러분이 당장 써볼 수 있는 /security-review 명령어를 중심으로 설명드리겠습니다. 작동 방식은 이렇습니다. 사람 보안 연구원이 코드를 리뷰하듯이, AI가 똑같이 수행합니다. 첫째, 코드를 읽고 함수·클래스·모듈 간 관계를 파악합니다. 둘째, 데이터 흐름과 권한 흐름을 추론합니다. 셋째, 보안 연구원처럼 위험도를 평가합니다. 그리고 AI가 코드의 의미 자체를 이해하기 때문에, 언어에 상관없이 분석할 수 있습니다.
