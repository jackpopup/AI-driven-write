## 1. 영상 개요

| 항목 | 내용 |
|------|------|
| **영상 제목** | [Claude Code Security 완전 해설] AI가 코드를 읽고 취약점을 추론합니다 |
| **러닝타임** | 약 15분 (목표: 14:30~15:00) |
| **영상 형태** | PPT 슬라이드 기반 해설 영상 (얼굴 노출 없음, 라이브 코드 시연 없음) |
| **나레이션 방식** | AI TTS (한국어) |
| **핵심 톤** | 기술적 신뢰감 + 실용적 긴박감. "이건 알아야 한다"는 느낌. 흥분보다는 명료함. |
| **디자인 컬러** | 배경 딥 네이비 (#0D1B2A), 강조 오렌지-코랄 (#FF6B47), 보조 화이트 (#F8F9FA) |

### 편집 기조

TTS 나레이션은 감정의 높낮이가 없으므로 편집이 리듬감과 임팩트를 전담한다. 슬라이드 전환, 줌인/아웃, 텍스트 애니메이션, SFX, BGM 볼륨 변화로 시각적 단조로움과 나레이션의 평탄함을 보완하는 것이 이 가이드의 핵심 목표다.

## 2. 인트로 구성 (0:00~0:05)

나레이션 시작 전 채널 인트로를 5초 내외로 처리한다.

### 구성 요소

- **채널 로고 애니메이션**: 로고가 좌측에서 슬라이드인 후 0.3초 대기, 채널명 타이포가 우측에서 페이드인
- **배경**: 딥 네이비 단색 또는 로우폴리 파티클 애니메이션 (어두운 테크 무드)
- **BGM 시작**: 인트로 BGM이 0:00에 시작, 0:04~0:05 구간에서 페이드아웃 후 메인 BGM으로 전환
- **SFX**: 로고 등장 시 짧은 전자음 (whoosh 계열, 0.5초 이내)
- **전환**: 인트로 마지막 프레임에서 슬라이드 1으로 하드컷 또는 0.2초 디졸브

## 3. 섹션별 편집 가이드

### 섹션 1: 훅 — 숫자 임팩트 [0:00~0:25] / 슬라이드 1

**목적**: 첫 25초 안에 시청자를 붙잡는 것. 이 구간이 이탈률을 결정한다.

#### 슬라이드 전환
- 인트로에서 슬라이드 1으로 하드컷 전환
- 자물쇠 금 가는 애니메이션이 0:00~0:08 구간에서 전개
- 0:08 시점에 "500+" 숫자가 등장 — 카운트업 애니메이션 적용 (0부터 500까지 약 1.5초)
- 숫자 등장 시 스케일 120% -> 100% 바운스 효과 추가

#### 자막/텍스트 오버레이
- "500+" 하단 소자막: "Anthropic이 오픈소스 코드베이스에서 발견한 실제 취약점 수"
- 소자막은 숫자 카운트업 완료 시점(0:10)에 페이드인
- 폰트: 가이드 섹션 4 참고

#### 그래픽/애니메이션
- 자물쇠 깨지는 애니메이션: PPT 원본 사용 또는 편집 프로그램에서 프레임 by 프레임으로 강조
- "500+" 숫자에 주황-코랄 글로우 효과 (Outer Glow, Spread 5px, Opacity 60%)
- 숫자 등장 직후 배경에 미세한 붉은 파티클 이펙트 0.5초 (선택 사항)

#### BGM 볼륨
- 나레이션 시작(0:05 추정) 직전 BGM -3dB 덕킹

#### SFX
- 자물쇠 깨지는 시점: 유리 깨지는 효과음 (짧고 선명하게, 볼륨 70%)
- "500+" 숫자 등장 시점: 임팩트 붐(sub bass hit) 1회, 볼륨 60%

### 섹션 2: 문제 제기 [0:25~2:00] / 슬라이드 2~3

**목적**: "우리 일이다"라는 공감대 형성. 긴박감 유지.

#### 슬라이드 2 (0:25~1:00): 보안 사고 사례

- **전환**: 슬라이드 1에서 0.3초 왼쪽 슬라이드 와이프
- **뉴스 카드 등장**: 카드 3장이 0.5초 간격으로 위에서 아래로 드롭인 (staggered 등장)
- **텍스트 오버레이**: 각 카드의 "피해 규모" 수치 (2,600+, 50%+)에 빨간색 강조 하이라이트
- **색 톤**: 이 슬라이드 전체에 붉은 오버레이 비넷 효과 (Opacity 15~20%)
- **SFX**: 뉴스 카드 등장 시 서류 넘기는 효과음 (3회, 0.3초 간격)
- **BGM**: 볼륨 유지, 별도 변화 없음

#### 슬라이드 3 (1:00~2:00): 기존 도구의 한계

- **전환**: 슬라이드 2에서 0.3초 페이드 전환
- **물음표 등장**: 슬라이드 로드와 동시에 중앙 물음표 스케일인 (80% -> 100%, 0.4초)
- **로고 나열**: SAST 도구 로고 3개가 0.5초 간격으로 좌 -> 우 순서로 페이드인
- **"규칙 기반 패턴 매칭" 태그**: 각 로고 등장 1초 후 태그 텍스트 페이드인
- **색 톤**: 회색 톤 유지. 전체적으로 차갑고 밋밋한 느낌 의도적으로 유지
- **나레이션 "바로 여기서 AI가 등장합니다" 발화 시점**: BGM 볼륨 살짝 상승 (+2dB, 0.5초), 슬라이드에 미세한 밝아지는 효과로 다음 섹션 예고
- **SFX**: 없음 (이 구간은 의도적으로 건조하게 유지)

### 섹션 3: 기존 SAST vs AI [2:00~4:15] / 슬라이드 4~7

**목적**: 개념 전환 구간. 비유 설명으로 이해를 돕는다. 시각 자료가 논리를 이끌어야 한다.

#### 슬라이드 4 (2:00~2:45): CCTV vs 탐정

- **전환**: 앞 섹션에서 0.5초 줌아웃 후 슬라이드 4 페이드인 (시각적 호흡)
- **좌우 분할 등장**: 왼쪽(CCTV/빨간 톤)이 먼저 0.4초 슬라이드인, 이후 중앙 구분선 등장, 이후 오른쪽(탐정/초록 톤) 0.4초 슬라이드인
- **불릿 텍스트**: 나레이션 흐름에 맞춰 순서대로 페이드인 (각 불릿당 약 1초 간격)
- **강조**: 오른쪽 "비즈니스 로직 결함 탐지" 불릿에 코랄 컬러 텍스트 강조 + 언더라인
- **SFX**: 왼쪽 등장 시 기계적인 클릭음, 오른쪽 등장 시 부드러운 차임벨 (대비 효과)

#### 슬라이드 5 (2:45~3:15): 맞춤법 검사기 vs 편집장

- **전환**: 0.3초 왼쪽 와이프
- **좌우 동시 등장**: 양쪽 일러스트 동시 페이드인 (0.5초)
- **중앙 하단 텍스트**: 나레이션 중반부(약 3:00)에 페이드인
- **별도 강조 없음**: 이 슬라이드는 개념 정착 구간. 시각적으로 안정적으로 유지

#### 슬라이드 6 (3:15~3:45): 비즈니스 로직 결함

- **전환**: 0.3초 페이드
- **카드 3장 등장**: 0.4초 간격 staggered 드롭인
- **경고 아이콘**: 각 카드 등장 직후 아이콘이 좌우로 짧게 흔들리는 애니메이션 (shake, 0.3초)
- **SFX**: 각 카드 등장 시 짧은 경고음 (삐- 계열, 낮은 볼륨 50%)

#### 슬라이드 7 (3:45~4:15): 500개 취약점 — 숫자 임팩트

- **전환**: 슬라이드 6에서 0.2초 하드컷 (의도적 임팩트)
- **"500+" 타이포 처리**: 슬라이드 1과 동일한 카운트업 애니메이션 재사용 (0 -> 500+, 1.2초)
- **배경**: 딥 네이비 + 오렌지-코랄 숫자 (스크립트 원안 유지)
- **스케일 효과**: 숫자 등장 후 120% -> 100% 바운스
- **BGM**: 이 슬라이드 등장 시 볼륨 +3dB 상승 (임팩트 강조), 나레이션 끝나며 원래 볼륨 복귀
- **SFX**: 임팩트 붐 1회 (섹션 1과 동일 사운드, 일관성 유지)
- **자막 없음**: 숫자만으로 임팩트. 텍스트 오버레이 최소화

### 섹션 4: Claude Code Security 소개 [4:15~5:30] / 슬라이드 8~9

**목적**: 제품 소개 구간. 신뢰감과 명료함이 핵심.

#### 슬라이드 8 (4:15~5:00): 작동 원리 아키텍처

- **전환**: 0.4초 페이드 (앞 임팩트 구간에서 차분하게 전환)
- **아키텍처 도식 등장**: "코드베이스 -> Claude AI -> 보안 리포트" 순서로 좌 -> 우 순차 등장 (각 요소 0.5초 간격)
- **Claude AI 내부 3단계**: 화살표가 그려지듯 등장 (draw-on 애니메이션) 후 3단계 텍스트 순차 페이드인
- **강조**: "모든 프로그래밍 언어 지원" 텍스트는 하단에 코랄 컬러 밑줄 + 마지막에 등장
- **나레이션 "2026년 2월 20일, Anthropic이 공식 발표한 기능입니다" 시점**: 슬라이드 상단에 날짜 스탬프 텍스트 페이드인 후 2초 후 페이드아웃 (소자막 처리)
- **BGM**: 안정적 볼륨 유지

#### 슬라이드 9 (5:00~5:30): 6가지 탐지 카테고리

- **전환**: 0.3초 왼쪽 와이프
- **카드 6개 등장**: 2x3 그리드, 좌상단부터 Z자 순서로 0.3초 간격 staggered 팝인 (scale 80% -> 100%)
- **"비즈니스 로직 결함" 카드**: 다른 카드보다 0.5초 늦게 등장 + 코랄 테두리 펄스 애니메이션 1회 (이 구간을 앞서 강조했으므로 시각적으로 연결)
- **나레이션 "나머지 카테고리는 화면을 참고해주시면 됩니다" 시점**: 전체 카드에 잠깐 밝아지는 하이라이트 효과 (0.5초)
- **SFX**: 카드 그룹 등장 완료 시 가볍고 경쾌한 팝 사운드 1회

### 섹션 5: /security-review 사용법 [5:30~7:15] / 슬라이드 10~12

**목적**: 핵심 기능 시연 구간. 실제처럼 보이게 만드는 것이 목표.

#### 슬라이드 10 (5:30~6:00): 명령어 소개

- **전환**: 0.3초 페이드
- **터미널 등장**: 터미널 창이 위에서 슬라이드다운 (0.4초)
- **"/security-review" 타이핑 애니메이션**: 글자가 한 자씩 타이핑되는 효과 (전체 0.8초), 끝에 커서 깜빡임 유지
- **글로우 효과**: 타이핑 완료 후 텍스트에 코랄 컬러 글로우 1.5초 지속
- **BGM**: 이 시점부터 약간 템포감 있는 구간으로 전환 (동일 트랙 내에서 리듬감 강조 파트)
- **SFX**: 타이핑 사운드 (keyboard click, 약 10회 연속, 볼륨 40%)

#### 슬라이드 11 (6:00~6:35): 결과 화면 (코드/터미널 슬라이드)

- **전환**: 0.3초 페이드
- **결과 화면 등장**: 터미널 창 전체가 페이드인 (0.5초)
- **심각도별 텍스트 하이라이트 순차 등장**:
  - Critical 항목: 빨간 배경 텍스트로 강조, 먼저 등장
  - High 항목: 주황 배경 텍스트, 0.5초 후 등장
  - Medium 항목: 노란 배경 텍스트, 0.5초 후 등장
- **구체적 해결책 텍스트**: 나레이션 "Prepared Statement로 변경하면 해결됩니다" 발화 직전에 해당 줄에 코랄 밑줄 강조 애니메이션
- **SFX**: 결과 화면 등장 시 데이터 스캔 효과음 (swoosh + beep 조합, 1초)

#### 슬라이드 12 (6:35~7:15): 비즈니스 로직 결함 탐지 예시 (코드 슬라이드)

- **전환**: 0.3초 왼쪽 와이프
- **코드 하이라이트 애니메이션**:
  - 왼쪽 "취약한 코드": 먼저 등장, 취약한 부분(쿠폰 중복 방지 로직 없는 줄)에 빨간 밑줄이 그려지듯 등장 (draw-on, 0.5초)
  - 오른쪽 "Claude 분석 결과": 1초 후 등장, 초록 배경으로 분석 텍스트 페이드인
- **"기존 SAST로는 탐지 불가능" 뱃지**: 나레이션 마지막 문장 발화 직전에 등장, 빨간 배경 + 흰 텍스트, 스케일 팝인 효과
- **SFX**: 왼쪽 코드 등장 시 오류 경고음 (짧은 buzz), 오른쪽 Claude 분석 등장 시 긍정적 차임

### 섹션 6: GitHub Actions 연동 [7:15~9:15] / 슬라이드 13~16

**목적**: 실무 적용 방법 전달. 순서와 흐름이 명확해야 한다.

#### 슬라이드 13 (7:15~7:45): PR 자동 보안 리뷰 플로우

- **전환**: 0.5초 페이드 (섹션 전환, 호흡 제공)
- **플로우 다이어그램 등장**: "PR 생성 -> Actions 트리거 -> Claude Security 실행 -> PR에 인라인 코멘트" 순서로 화살표와 함께 좌에서 우로 순차 등장 (각 요소 0.6초 간격)
- **화살표**: 그려지듯 등장하는 draw-on 효과
- **"PR에 인라인 코멘트" 마지막 요소**: 코랄 강조 테두리 펄스
- **BGM**: 이 섹션부터 약간 더 밝고 구체적인 무드의 파트 (자동화/효율 느낌)

#### 슬라이드 14 (7:45~8:15): YAML 코드 (코드 슬라이드)

- **전환**: 0.3초 페이드
- **코드 슬라이드 등장**: 전체 코드창 페이드인 (0.4초)
- **핵심 3줄 하이라이트 순차 등장**:
  1. `on: pull_request` — 코랄 배경 하이라이트, 1초 노출 후 다음으로
  2. `uses: anthropic/claude-code-action` — 같은 방식
  3. `command: /security-review` — 같은 방식 + 마지막에 강조 테두리 1초 유지

## 4. 자막 스타일 가이드

TTS 나레이션이므로 발화 내용의 자막은 원칙적으로 표시하지 않는다. 단, 아래의 경우에 한하여 오버레이 텍스트를 사용한다.

| 자막 유형 | 용도 | 스타일 |
|-----------|------|--------|
| **강조 소자막** | 핵심 수치, 날짜, 중요 용어 | 화면 하단 중앙, 코랄 텍스트 |
| **코드/명령어** | 터미널 명령어 노출 | 모노스페이스 폰트 (JetBrains Mono 또는 Fira Code), 흰색, 터미널 배경 |
| **슬라이드 내 텍스트** | PPT 내 텍스트 (편집 없음) | PPT 원본 유지 |

### 폰트

| 유형 | 폰트 | 크기 | 색상 |
|------|------|------|------|
| 슬라이드 주제목 | Pretendard ExtraBold | 48~60pt | 화이트 (#F8F9FA) |
| 슬라이드 부제목 | Pretendard SemiBold | 28~36pt | 화이트 (#F8F9FA) |
| 강조 오버레이 자막 | Pretendard Bold | 18~22pt | 코랄 (#FF6B47) |
| 소자막 (보조 정보) | Pretendard Regular | 14~16pt | 라이트 그레이 (#B0BEC5) |
| 코드/명령어 | JetBrains Mono | 16~24pt | 화이트 또는 코랄 |

### 위치

- 강조 소자막: 화면 하단 중앙, 하단 기준 10% 내

## 8. 편집 시 주의사항

### TTS 나레이션 특성 관련

1. **발화 속도 균일**: TTS는 강세와 속도 변화가 없으므로, 편집에서 슬라이드 전환 타이밍을 나레이션 문장 완료 직후 0.2~0.3초 딜레이 후 전환한다. 문장이 끝나기 전 전환하면 어색함이 강조된다.

2. **침묵 구간 처리**: TTS 문단 간 침묵 구간(0.5초~1초)이 발생할 수 있다. 이 구간에 SFX 또는 BGM 볼륨 살짝 상승으로 채워 영상이 멈춘 느낌을 방지한다.

3. **감정 대신 시각**: TTS가 감정 없이 전달하는 구간(특히 섹션 1, 7, 23의 임팩트 숫자 구간)은 그래픽 애니메이션과 SFX로 감정을 대체한다. 시청자가 TTS임을 인식하기 전에 시각 요소가 먼저 반응해야 한다.

4. **비음악적 처리 자제**: TTS와 동일한 인상을 주는 단조로운 배경음은 피한다. BGM은 반드시 멜로딕 요소(선율이나 화음)가 있는 것으로 선택한다.

### PPT 기반 영상 관련

1. **슬라이드 전환 기본 원칙**: 나레이션 내용과 슬라이드가 동기화되어야 한다. 나레이션이 다음 슬라이드 내용을 언급하기 시작할 때 전환한다. 전환이 너무 이르면 시청자가 텍스트를 읽기 전에 다음으로 넘어가는 느낌이 든다.

2. **시각적 단조로움 방지 3가지 기법**:
   - 줌인/아웃: 슬라이드 내에서 강조 부분으로 서서히 줌인 (최대 110~120%)
   - 패닝: 넓은 슬라이드 (비교표, 코드 블록)에서 좌우 패닝으로 내용 안내
   - 요소 순차 등장: PPT 원본 애니메이션이 없더라도 편집에서 요소별 순차 등장 처리

3. **코드 슬라이드 처리 (슬라이드 11, 12, 14, 15, 18)**:
   - 반드시 코드 하이라이트 애니메이션 적용 (섹션별 가이드 참고)
   - 코드 폰트가 선명하게 보여야 함. 슬라이드 해상도 확인 후 필요 시 리소스 재요청
   - 코드 줄 번호가 있다면 강조 줄 번호에 코랄 컬러 적용

4. **숫자 임팩트 슬라이드 (슬라이드 1, 7)**:
   - 두 슬라이드 모두 카운트업 애니메이션 + 스케일 바운스 적용 (일관성)
   - 카운트업은 0에서 시작, 약 1~1.5초 소요
   - 숫자 등장 시 SFX 임팩트 붐 필수 (두 구간 동일 사운드로 연결감 부여)

5. **영상 해상도**: 최종 출력 1920x1080 (FHD), 30fps 또는 60fps 선택 가능. 유튜브 업로드 기준 H.264 인코딩 권장.

6. **색공간**: sRGB 기준 작업. 딥 네이비 (#0D1B2A)가 너무 어둡거나 밝게 출력되지 않도록 모니터 캘리브레이션 후 작업 권장.
