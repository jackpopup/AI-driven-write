# Claude Code Security 해설 영상 - TTS 스크립트 (Final)

여러분이 지금 운영하고 있는 서비스, 그 코드 안에 여러분이 모르는 구멍이 있다면 어떨까요. Anthropic이 오픈소스 코드베이스를 분석한 결과, 500개 이상의 취약점이 발견됐습니다. 기존 보안 도구로는 한 번도 잡히지 않았던 것들이요.

"보안 사고, 우리 회사는 괜찮겠지." 그런데 현실을 보면요, MOVEit 공급망 공격으로 2,600개 넘는 조직이 한꺼번에 뚫렸습니다. Log4Shell은 전 세계 서버의 절반 이상에 영향을 미쳤고요. 공통점은 코드 안에 있던 취약점을 아무도 발견하지 못한 채 운영하고 있었다는 겁니다.

여러분 회사에서도 SonarQube, ESLint, Semgrep 같은 보안 도구를 쓰고 계실 겁니다. 이 도구들이 나쁜 건 아닙니다. 그런데 근본적인 한계가 있습니다. 전부 "규칙 기반 패턴 매칭"으로 동작해요. 미리 정해놓은 규칙에 맞는 패턴이 있으면 경고를 띄우는 방식입니다. 패턴은 잡지만, 맥락은 이해하지 못하는 거예요. 바로 여기서 AI가 등장합니다.

비유로 설명드리겠습니다. 기존 SAST는 CCTV입니다. "SQL 쿼리에 사용자 입력이 직접 들어갔다"는 규칙에 맞으면 경고를 띄웁니다. 반면 Claude Code Security는 탐정입니다. 코드를 처음부터 끝까지 읽고, "이 함수에서 저 함수를 호출하는데, 이 흐름에서 권한 체크가 빠져 있다"는 식으로 추론합니다.

하나 더. 기존 SAST는 맞춤법 검사기입니다. 오탈자는 잡지만, 글의 논리가 앞뒤가 안 맞는 건 못 잡습니다. Claude Code Security는 편집장입니다. 원고를 처음부터 끝까지 읽고, "3번째 문단의 논리가 1번째 문단과 모순된다"를 짚어냅니다.

구체적으로 보겠습니다. 쿠폰 중복 적용으로 무한 할인, 일반 사용자가 관리자 API 접근, 클라이언트에서 결제 금액 조작. 코드 문법상으로는 전혀 오류가 없습니다. 패턴 매칭으로는 절대 잡을 수 없어요. 코드의 "의미"를 이해해야만 발견할 수 있는 취약점들입니다.

실제 성과입니다. Anthropic 연구팀이 최신 모델 Claude Opus 4.6으로 오픈소스 코드베이스를 분석한 결과, 500개 이상의 취약점이 발견됐습니다. 기존 도구가 수년간 돌아가면서도 잡지 못했던 것들이요. 실험실이 아니라 실제 운영 중인 프로젝트에서 나온 숫자입니다. 이 동일한 AI 분석 역량이 /security-review 명령어에도 적용됩니다.

2026년 2월 20일, Anthropic이 공식 발표한 기능입니다. 크게 두 가지로 나뉩니다. 하나는 터미널에서 바로 쓸 수 있는 /security-review 명령어, 다른 하나는 팀 단위로 전체 코드베이스를 자율 스캔하는 웹 대시보드입니다. 오늘은 여러분이 당장 써볼 수 있는 /security-review 명령어를 중심으로 설명드리겠습니다. 작동 방식은 이렇습니다. 사람 보안 연구원이 코드를 리뷰하듯이, AI가 똑같이 수행합니다. 첫째, 코드를 읽고 함수·클래스·모듈 간 관계를 파악합니다. 둘째, 데이터 흐름과 권한 흐름을 추론합니다. 셋째, 보안 연구원처럼 위험도를 평가합니다. 그리고 AI가 코드의 의미 자체를 이해하기 때문에, 언어에 상관없이 분석할 수 있습니다.

탐지 범위를 보겠습니다. 화면에 보이는 6가지 카테고리입니다. 핵심만 짚으면, 인젝션 공격과 인증 결함 같은 전통적인 취약점은 물론이고, 앞서 말씀드린 비즈니스 로직 결함까지 잡아냅니다. 나머지 카테고리는 화면을 참고해주시면 됩니다.

사용법은 놀라울 정도로 간단합니다. Claude Code 터미널에서 /security-review를 입력합니다. 끝입니다. 설정 파일도, 규칙 정의도 필요 없습니다. 참고로 이 기능은 Pro 플랜 이상에서 사용 가능하고, 상세한 플랜 비교는 뒤에서 다루겠습니다.

결과는 이렇게 나옵니다. 심각도별로 정리되고, 각 항목에 파일명, 줄 번호, 수정 방법까지 함께 표시됩니다. 단순히 "SQL 인젝션 위험"이 아니라, "이 함수에서 사용자 입력이 검증 없이 쿼리에 전달되고 있으며, Prepared Statement로 변경하면 해결됩니다"라는 식으로 구체적인 해결책을 제시합니다.

예시를 보겠습니다. 쿠폰 적용 함수입니다. 코드 문법상 문제 없고, ESLint도 통과합니다. 하지만 Claude는 이렇게 분석합니다. "동일 쿠폰의 중복 적용을 방지하는 로직이 없습니다. 공격자가 반복 호출하여 무한 할인을 받을 수 있습니다." 규칙 기반 도구로는 절대 잡을 수 없는 문제입니다.

매번 수동으로 실행하기 귀찮으시다고요? GitHub Actions와 연동하면 PR을 올릴 때마다 자동으로 보안 리뷰가 실행됩니다. 분석이 끝나면 PR에 인라인 코멘트로 결과가 표시됩니다.

설정 파일의 핵심은 딱 3줄입니다. on: pull_request로 PR 트리거, uses: anthropic/claude-code-action으로 Claude 호출, command: /security-review로 명령어 지정. 이 3줄만 이해하시면 나머지는 복사-붙여넣기로 충분합니다. 전체 YAML은 PPT 부록에 넣어드리겠습니다.

실제로 PR에 이렇게 인라인 코멘트가 달립니다. 구체적인 위치와 함께 설명이 달리기 때문에, 보안 전문 지식이 없어도 어디를 고쳐야 하는지 바로 알 수 있습니다.

비용입니다. 소규모 PR은 약 50센트, 중규모 1달러 75센트, 대규모 4달러 50센트 정도입니다. 시니어 보안 엔지니어 연봉 1억 원과 비교하면, PR당 50센트로 24시간 보안 리뷰를 돌릴 수 있다는 건 기존에 불가능했던 일입니다.

한 단계 더 나아갈 수 있습니다. 프로젝트 루트에 .claude/commands/security-review.md 파일을 만들면, 여러분 조직만의 보안 규칙을 추가할 수 있습니다.

마크다운으로 자연어로 작성하면 됩니다. "API에 인증 미들웨어가 적용되어 있는지 확인해라." "결제 금액 검증이 서버 사이드에서 이루어지는지 확인해라." 이렇게 적으면 Claude가 이 규칙들까지 반영해서 보안 리뷰를 수행합니다.

왼쪽이 기본 결과, 오른쪽이 커스텀 규칙 적용 후입니다. "결제 API에 금액 검증 로직이 서버 사이드에 없습니다"와 같은, 우리 비즈니스에 특화된 보안 체크가 자동으로 이루어집니다. 파일 하나 추가하는 것만으로요.

어떤 플랜에서 뭘 쓸 수 있는지 정리합니다. /security-review는 모든 유료 플랜에서 사용 가능합니다. GitHub Actions도 전부 가능한데, 오픈소스 메인테이너만 무료입니다. 전체 코드베이스 자율 스캔과 웹 대시보드는 Team과 Enterprise 대상으로 현재 제한적 리서치 프리뷰 상태입니다. 오픈소스 메인테이너는 무료 우선 접근이 가능합니다.

도입 시나리오 3가지입니다. 첫 번째, 소규모 팀이라면 Pro 플랜에서 /security-review를 수동 실행하시면 됩니다. 꿀팁은, Pre-commit hook에 추가하면 커밋할 때마다 자동 실행됩니다. 다만 로컬에서 실행되더라도 AI 분석은 클라우드에서 이루어지기 때문에, 구독 플랜의 사용량이 차감됩니다. 별도 API 과금은 아니지만 무료는 아닌 점 참고해주세요. 취약점이 있으면 커밋 자체가 차단됩니다. 두 번째, 5명에서 15명 규모라면 Team 플랜에 GitHub Actions를 연동하세요. 하루 PR 5개 기준 월 약 75달러입니다. 세 번째, 오픈소스 프로젝트는 전부 무료입니다. 전체 스캔, 대시보드까지 무료 제공됩니다.

자, 마무리하기 전에 꼭 말씀드려야 할 것이 있습니다. Claude Code Security가 아무리 좋아도, 이것만으로 보안이 완벽해지지는 않습니다.

첫째, 이건 대체가 아니라 보완입니다. 기존 SAST, 코드 리뷰, 침투 테스트 위에 한 겹 더 얹는 레이어드 방어 전략이에요.

둘째, AI가 놓치는 취약점이 있을 수 있고, 문제가 아닌 것을 문제라고 보고할 수도 있습니다. 최종 판단은 사람이 해야 합니다.

셋째, npm 패키지나 Python 라이브러리 같은 의존성 취약점은 Dependabot이나 Snyk과 병행하셔야 합니다. 그리고 외부 PR에 대해서는 프롬프트 인젝션 방지를 위해 수동 승인 후 실행을 권장합니다.

정리하겠습니다. 첫째, Claude Code Security는 AI가 사람 보안 연구원처럼 코드를 읽고 추론해서 취약점을 찾아냅니다. 비즈니스 로직 결함까지요. 둘째, /security-review 한 줄이면 시작할 수 있습니다. 셋째, 대체가 아니라 보완입니다. 비용은 PR당 50센트입니다.

터미널에서의 /security-review는 Pro 플랜 이상이면 지금 바로 시작하실 수 있습니다. Claude Code를 열고, /security-review를 입력해보세요. 팀 단위 전체 스캔 대시보드는 현재 순차적으로 오픈 중이니, 관심 있으신 분은 Anthropic 공식 페이지에서 대기자 신청을 하시면 됩니다. 관련 자료 링크는 영상 설명란에 정리해두었습니다.

이 영상이 도움이 되셨다면 좋아요 한 번 부탁드리겠습니다. "우리 팀에 도입하려면 어떻게 해야 하나요?"라든가, "이 부분은 좀 더 깊게 다뤄주세요" 같은 의견은 댓글로 남겨주시면 반영하겠습니다. 구독과 알림 설정 해두시면 다음 영상도 놓치지 않으실 수 있습니다. 감사합니다.
